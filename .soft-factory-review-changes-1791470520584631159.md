### Behavior summary

All property names in `software-factory.json` are now lower camelCase (`googleDrive`, `customSkills`, `customSkills.codeReview`, …). `config.Load` now checks names before the typed `json.Unmarshal` runs. It walks the raw JSON token stream at the top level and inside every `googleDrive` / `customSkills` object, including repeated keys. It rejects any obsolete name (`google_drive`, `custom-skills`, `code-review-skill`, the nested kebab-case skill keys) and any known name with the wrong case (`Documents`, `googledrive`, `codereview`, …), whatever the value is. The error names the offending path and its canonical replacement. Other unknown keys are still ignored. Validation errors and the custom-skill errors in `runWorkflow` now use canonical paths. The README and a new spec document the breaking change and the manual migration. Tests were updated to the new names, and new tables cover rejections.

### 5d. Ordered member reader

```diff
+// member is one name and value of a JSON object.
+type member struct {
+	name  string
+	value json.RawMessage
+}
+
+// objectMembers returns every member of a valid JSON object in document
+// order, including repeated names, which a map keeps only once. Non-object
+// values have no members.
+func objectMembers(data []byte) ([]member, error) {
+	dec := json.NewDecoder(bytes.NewReader(data))
+	tok, err := dec.Token()
+	if err != nil {
+		return nil, fmt.Errorf("read object: %w", err)
+	}
+	if tok != json.Delim('{') {
+		return nil, nil
+	}
+	var members []member
+	for dec.More() {
+		tok, err := dec.Token()
+		if err != nil {
+			return nil, fmt.Errorf("read object name: %w", err)
+		}
+		name, ok := tok.(string)
+		if !ok {
+			return nil, fmt.Errorf("read object name: unexpected %v", tok)
+		}
+		var value json.RawMessage
+		if err := dec.Decode(&value); err != nil {
+			return nil, fmt.Errorf("read %s: %w", name, err)
+		}
+		members = append(members, member{name, value})
+	}
+	return members, nil
+}
```

## Findings

No correctness, security, or regression defects were found in the branch changes. The low-severity items below are optional.

1. **Low (documentation accuracy): the comment overstates the "non-object" gate.**
   - **Location:** [config.go:81-85](soft-factory/internal/config/config.go:81).
   - **Trigger:** a `software-factory.json` whose entire content is `null`.
   - **Impact:** `json.Unmarshal` into a map accepts `null`, `objectMembers` returns no members, and the typed decode leaves the zero `Config`, so the file loads as an empty configuration. The comment says non-object configuration is rejected. The behavior predates the branch (the base typed decode also accepted `null`), so this is not a regression, and no setting is silently dropped.
   - **Fix:** change the comment to "Reject malformed and array or scalar configuration…", or add `if fields == nil { return Config{}, fmt.Errorf("parse factory configuration: expected a JSON object") }` with a test, if `null` should be rejected.

2. **Low (test coverage): a branch in the name checker has no test.**
   - **Location:** [config.go:152-157](soft-factory/internal/config/config.go:152).
   - **Trigger:** a non-null, non-object value for a known parent, such as `{"customSkills":"x"}` or `{"googleDrive":[]}`.
   - **Impact:** The code says these values are "reported by the typed decode", and by inspection they produce `parse factory configuration: json: cannot unmarshal …`. No test pins that down, so a future change to `objectMembers` could quietly alter this path.
   - **Fix:** add one or two rows to a load-error table that assert the `parse factory configuration` prefix.

No other actionable issue is supported by the evidence. The things checked include: the unescaping of key tokens, Unicode case folding being the same as `encoding/json`, duplicate-key merging, sorted reporting order, and canonical paths in every `Validate` and `runWorkflow` message.
